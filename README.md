# 폴짝 · jump-up

저마다의 봄, 나만의 속도. 현재 상태와 목표에 맞춘 작은 미션, 대화 연습, 내 개구리 꾸미기를 제공하는 모바일 웹앱입니다.

## 웹에서 배포하기

[Vercel에서 새 프로젝트 만들기](https://vercel.com/new)

1. Vercel에 로그인하고 **Add New → Project**에서 GitHub 저장소 **ohead-yonsei/jump-up**을 가져옵니다.
2. **Framework: Next.js**, **Root Directory: `./`**, **Node.js: 22.x**를 확인합니다. 설치와 빌드 명령은 `vercel.json`에 준비되어 있습니다.
3. 환경변수 없이 **Deploy**를 누르면 앱과 예시 대화를 사용할 수 있습니다. 발표 화면은 배포 주소 뒤에 `/demo`를 붙여 엽니다.

프로젝트를 GitHub 저장소에 연결하면 이후 `main`에 push한 변경 사항도 자동 배포됩니다. [Vercel의 GitHub 배포 안내](https://vercel.com/docs/git/vercel-for-github)

이 저장소는 표준 Next.js 프로젝트입니다. `/api/chat` 서버 경로가 있으므로 Vercel 또는 Node.js 서버로 배포합니다. GitHub Pages의 정적 파일 배포만으로는 전체 기능을 실행할 수 없습니다.

## 들어 있는 기능

- 휴대폰 앱처럼 쓰는 화면: 시작 스플래시, 상단 앱 바, 떠 있는 하단 탭 바, 바텀시트 메뉴, 홈 화면 설치(PWA)를 제공합니다. 큰 화면에서도 휴대폰 폭으로 보여줍니다.
- 탭은 세 개입니다. **연못**(홈, 친구 옆의 ‘꾸미기’로 옷장을 열어요), **연습·도움**(대화 연습 · 도움 받을 곳 · 가볼 만한 곳), **기록**. 긴급 도움(상단의 하트)은 모든 화면에 있습니다.
- 연못(홈)은 휴대폰 한 화면에 들어옵니다. 친구가 있는 연못, 오늘의 에너지 세 가지, 미션 한 장(‘다른 미션’으로 넘겨요), 기수 자리 하나가 스크롤 없이 보이고, ‘나의 봄 여정’(단계와 다음 단계 고르기)은 에너지 옆의 단계 이름을 누르면 시트로 열립니다.
- 3D 개구리 친구(three.js): 톡 누르면 폴짝 뛰고, 머리를 누르면 좋아하고, 길게 누르면 두 팔을 벌려 안아주고, 옆으로 밀면 돌아봅니다. 미션을 마치면 함께 기뻐합니다.
- 친구는 알 → 올챙이 → 아기 개구리 → 어른 개구리 → 다 자란 개구리로 자랍니다. 무엇이든 한 날(쉬어가기 포함)이 1·3·7·14일이 되면 다음 모습이 되고, 줄어들지 않아요. 0.24.0 전에 만든 친구는 어른 개구리에서 이어 자랍니다. 다섯 모습은 `/growth`에서 나란히 볼 수 있어요.
- 처음 방문 시 별명·8가지 색으로 캐릭터를 만들고 상태·목표·에너지를 선택합니다.
- 자기 진단의 생활 범위에 ‘일상 생활을 잘 지내고 있지만 가끔 다시 혼자 있고 싶어요’를 고를 수 있습니다. 이 선택을 하면 혼자만의 시간을 건강하게 보내는 ‘나만의 썰물’ 미션 4개가 연못의 ‘나만의 썰물’ 버튼에 열립니다.
- 3개 목표와 4개 시작점에 따른 84개 미션을 한 번에 하나씩 제안합니다. ‘다른 미션’을 눌러도 오늘의 미션을 모두 볼 때까지 같은 미션이 반복되지 않고, 날마다 순서가 바뀝니다. 다음 단계는 직접 선택합니다.
- 오늘의 에너지는 세 가지입니다(쉬어갈래요 · 작은 것 하나 · 조금 더 해볼래요). 미션의 크기는 내 단계를 기준으로 정해져요: 가장 작은 미션만 / 내 단계보다 한 칸 아래까지 / 내 단계까지. 고르면 개구리도 같은 마음이 되고, 미션을 마치면 그 행동을 알아봐 주는 한마디를 건넵니다. 3일 넘게 쉬다 돌아오면 연못에서 환영 선물을, 밤 11시~새벽 5시에는 ‘잠들기 전 1분’ 버튼을 보여줍니다.
- 활동으로 잎 포인트를 모아 모자·안경·옷·소품·표정 28개 아이템을 소장하고, 캐릭터 시트에서 가져온 15개 코디 예시를 한 번에 입어볼 수 있습니다.
- 카페 주문·병원 진료 예약 전화·아르바이트 면접·지원기관에 처음 문의하기·안부 인사를 연습합니다. 상대의 말을 소리로 듣고, 마이크로 답해볼 수 있습니다. 연습 전 숨 고르기를 고를 수 있습니다.
- 실증용으로 주간 ‘나의 마음 변화’(선택), ‘폴짝에게 한마디’, 참여 코드, CSV 내보내기를 제공합니다.
- 기관에서 받은 기수 코드(또는 참여 링크)로 기수에 함께할 수 있습니다. 동의한 뒤에 남긴 기록만 기수 운영진에게 전달되고, 기수에서 나가면 보낸 기록도 지워집니다. 운영진은 `/ops`에서 참여 현황을 보고 CSV로 내려받습니다(아래 ‘기수 운영’).
- 기수에 함께하면 ‘연잎 한 장’ 연못이 열립니다. 사진 한 장을 찍거나 골라 띄우기로 하면 연잎 모양으로 쌓이고, 같은 기수 사람들만 함께 봅니다. 사진마다 띄울지 직접 고르고, 다른 참여자에게는 사진과 날짜만 보입니다(누가 띄웠는지, 좋아요, 숫자 없음). 위치 같은 사진 정보는 지우고 올리며, 내 연잎은 언제든 내릴 수 있고 운영진은 연못에 맞지 않는 연잎을 내려둘 수 있습니다.
- 연습·도움 탭의 ‘도움 받을 곳’에서 ‘나에게 맞는 도움 찾기’로 마음·연락 방법·나이·지역에 맞는 기관 15곳을 고르고, 기관마다 받을 수 있는 도움·이용 대상·시작 방법·처음 연락할 문장을 보여줍니다. 긴급은 아니지만 이야기가 필요할 때의 연락처를 따로 모았습니다.
- 선택적 기기 저장, 기록 CSV 내보내기, 홈 화면 설치 안내를 제공합니다.
- `/demo`의 7개 발표 장면은 가상 데이터로 체험하며 개인 저장 기록에 접근하지 않습니다.

설계 원칙과 계획서 대응표는 [docs/design-notes.md](docs/design-notes.md), 버전별 변경은 [CHANGELOG.md](CHANGELOG.md)에 있습니다.

3D 캐릭터는 `lib/frog-scene.ts`에서 코드로 만들고, 목록용 썸네일은 하나의 렌더러로 그려 재사용합니다. WebGL을 쓸 수 없는 브라우저에서는 기존 일러스트로 대신 보여줍니다.

## 로컬 실행

Node.js 22와 npm을 사용합니다. nvm 사용자는 `nvm use`로 버전을 맞출 수 있습니다.

```sh
npm ci
npm run dev
```

기본 주소는 `http://localhost:3000`입니다. 배포 모드 실행은 다음과 같습니다.

```sh
npm run build
npm start
```

## AI 대화 연결

AI 대화는 팀이 운영하는 Ollama 서버를 먼저 쓰고, 연결되지 않으면 앱 안의 예시 대화로 자연스럽게 이어갑니다. 예시 대화도 사용자가 물은 말(카페인, 가격, 준비물 등)에 맞춰 답합니다.

Vercel 프로젝트의 **Settings → Environment Variables**에 아래 값을 넣고 다시 배포합니다. 로컬에서는 `.env.example`을 `.env.local`로 복사해 채웁니다.

| 변수 | 용도 |
| --- | --- |
| `CHAT_BASE_URL` | 팀 Ollama 서버의 https 주소(예: Tailscale Funnel 주소). 저장소에 적지 말고 환경변수로만 넣어요. |
| `CHAT_MODEL` | 사용할 모델. 한국어 역할극 비교 결과 `gemma3:12b`를 기본값으로 써요. |
| `CHAT_API_KEY` | 서버 앞에 토큰을 확인하는 프록시를 둘 때만. `Authorization: Bearer`로 보냅니다. |
| `OPENAI_API_KEY`, `OPENAI_MODEL` | 선택. 팀 서버를 설정하지 않았을 때만 사용해요. |
| `KAKAO_REST_API_KEY` | 선택. ‘가볼 만한 곳’에서 가까운 카페·공원·도서관·편의점 목록을 앱 안에 보여줄 때 써요. [카카오 디벨로퍼스](https://developers.kakao.com)에서 앱을 만들고 받은 REST API 키예요(카카오맵 사용 설정이 필요할 수 있어요). 없으면 지도 앱 바로가기만 보여요. |

역할극 프롬프트와 안전 규칙은 `lib/chat-service.ts`에 있습니다. 상황마다 누가 말하는지, 존댓말/반말, 상대가 아는 정보, 예시 한 턴을 정해 두고(`facts`), `systemPrompt`가 상대 역할의 답을, `hintPrompt`가 대화 기록을 바깥에서 읽고 ‘내가 이어서 할 말’ 2개를 따로 만듭니다(같은 호출에서 만들면 직원·친구의 말이 추천 문장에 섞였어요). 앱은 답(`POST /api/chat`)을 먼저 보여주고, 추천 문장(`POST /api/chat?hints=1`)은 뒤이어 받아요. 답이 상황의 말투를 벗어나면 한 번 더 받고, 너무 길면 앞 문장과 마지막 질문만 남기며, 고맙다·또 보자로 끝나면 남는 질문 없이 마무리합니다. 프롬프트·규칙·AI 이야기를 꺼내면 상황 안에서 짧게 넘기는 말로 바꾸고, 개인정보 요구·판단하는 말·위기 표현은 한 번 더 걸러냅니다. 연습 탭을 열면 모델을 미리 메모리에 올려 첫 답이 늦지 않게 합니다.

Funnel로 연 주소는 인터넷 어디서나 닿기 때문에, 토큰을 확인하는 프록시를 앞에 두고 같은 토큰을 `CHAT_API_KEY`로 넣어요(운영 서버는 2026-10-27부터 키 없이 오는 요청을 401로 막습니다). 로컬에서 실제 모델로 시험할 때도 `.env.local`에 같은 키가 있어야 해요. 사용자는 AI 대화를 시작하기 전에 ‘팀이 운영하는 AI 서버로 전송’에 동의하며, 폴짝은 대화 원문을 저장하지 않습니다.

## 기수 운영

기관 한 곳과 한 달 단위 기수로 실증할 때 씁니다. 환경변수가 없으면 배포 사이트에서는 기수 기능이 보이지 않고, 지금처럼 모든 기록이 기기에만 남아요.

| 변수 | 용도 |
| --- | --- |
| `SUPABASE_URL` | Supabase 프로젝트 주소(`https://….supabase.co`). |
| `SUPABASE_SECRET_KEY` | Supabase의 서버 전용 비밀 키(`sb_secret_…`, 예전 `service_role` 키도 돼요). `NEXT_PUBLIC_`을 붙이지 말고 서버에만 둬요. `SUPABASE_SERVICE_ROLE_KEY` 이름으로 넣어도 돼요. |
| `OPS_ADMIN_KEY` | 팀 관리자 키(12자 이상, 길고 무작위로). `/ops` 로그인과 운영자 세션 서명에 쓰여요. 바꾸면 모든 운영자가 다시 로그인해요. |
| `CRON_SECRET` | 선택. 넣으면 `/api/keepalive`가 Vercel Cron의 호출만 받아요(없으면 누구나 부를 수 있지만 주소마다 1분에 6번까지). |

1. [Supabase](https://supabase.com)에서 프로젝트를 만들고(서울 리전 권장), SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql)을 한 번 실행합니다. 모든 표에 행 수준 보안이 켜지고, 비밀 키로만 읽고 쓸 수 있어요. 연잎 사진을 담는 비공개 Storage 버킷 `lily-pads`도 함께 만들어져요. 0.25.0 전에 이미 실행했다면 같은 파일을 한 번 더 실행하면 돼요(있는 표는 그대로 두고 `pads` 표와 버킷만 더해요).
2. Vercel 프로젝트의 **Settings → Environment Variables**에 위 세 값을 넣고 다시 배포합니다.
3. `/ops`에서 관리자 키로 들어가 **새 기수 열기**를 누릅니다. 기본 기간은 30일이에요. 기수 코드와 운영자 코드가 나오는데, **운영자 코드는 한 번만 보여요.**
4. 기관 담당자에게 운영자 코드를, 참여자에게는 기수 화면의 **참여 링크**(`/?join=기수코드`)나 기수 코드를 전합니다. 링크를 열면 ‘기록’ 탭에 코드가 채워져 있고, 참여자가 전달되는 내용을 읽고 동의해야 참여가 시작돼요.
5. 기관 담당자는 `/ops`에 운영자 코드로 들어가 자기 기수만 봅니다(참여 코드, 연 날, 활동한 날, 최근 7일, 마음 체크 처음→최근, 연락 버튼, 한마디 수, CSV). 기간 연장(1주·30일·날짜 지정)과 ‘연잎 한 장’ 사진 내려두기도 여기서 해요. 팀은 모든 기수를 봐요.

- 참여자는 가명인 참여 코드로만 구분돼요. 한 기수 안에서 같은 참여 코드는 쓸 수 없어요. 실제 참여자와 참여 코드는 기관에서 따로 이어서 관리해 주세요.
- 기수에 함께한 뒤의 기록만 보내요(대화 원문은 보내지 않아요). 기록을 남기고 약 2초 뒤, 그리고 앱을 다시 열거나 인터넷이 다시 연결될 때 보내요. 어떤 기록을 보냈는지는 기록마다 기억해서, 기기 시계가 틀려도 빠지거나 두 번 가지 않아요. 서버는 정해진 항목만 다시 골라 담고, 한 사람당 2,000개까지 받아요.
- 참여자 화면에는 ‘나를 포함해 N명’처럼 함께하는 사람 수만 보여요. 다른 사람의 기록이나 참여 코드는 보이지 않아요.
- ‘연잎 한 장’ 사진은 참여자가 한 장씩 띄우기로 고른 것만 올라가요. 기기에서 가운데를 800px 정사각형 JPEG로 다시 그려 위치·기기 정보를 빼고, 서버가 한 번 더 걸러(EXIF·XMP·IPTC·주석, 끝 뒤에 붙은 데이터) 비공개 버킷에 넣어요. 같은 기수의 참여 토큰이 있어야 앱 서버를 거쳐 볼 수 있고, 다른 기수와 바깥에서는 볼 수 없어요. 한 사람당 60장까지 띄워둘 수 있어요.
- 운영자 화면의 ‘연잎 한 장’에서 사진과 띄운 사람의 참여 코드를 보고 ‘내려두기’로 연못에서 숨겨요. 지우지는 않아서 띄운 사람에게는 ‘운영진이 잠시 내려두었어요’로 보이고, ‘다시 띄우기’로 되돌릴 수 있어요. 참여자가 연잎을 내리거나 기수에서 나가면 사진도 지워져요.
- 참여자가 ‘기수에서 나가기’나 ‘모두 지우기’를 누르면 서버의 그 사람 기록이 바로 지워져요. 마친 기수에는 새로 들어올 수 없지만, 이미 함께한 사람의 기록은 계속 받아요.
- 운영자 코드를 잃어버리면 팀이 기수 화면에서 새로 만들어요. 이전 코드는 바로 막히고, 이전 코드로 들어와 있던 화면도 다음 요청부터 다시 로그인해야 해요.
- Supabase 무료 플랜은 7일 동안 데이터베이스 요청이 적으면 프로젝트를 일시중지해요. 그래서 Vercel Cron이 매일 한 번(UTC 0시, 한국 오전 9시 무렵) `/api/keepalive`를 불러 기수 표를 한 줄 읽어요(`vercel.json`). Vercel 프로젝트의 **Settings → Cron Jobs**에서 실행 기록을 볼 수 있고, 응답이 502면 Supabase가 멈췄거나 닿지 않는 거예요. 그래도 일시중지 안내 메일이 오면 Supabase 대시보드에서 프로젝트를 한 번 열어 주세요. 멈춘 프로젝트는 1년 안에 **Resume project**로 그대로 되살릴 수 있어요.
- 로컬에서는 Supabase 없이 `.data/cohorts.json`(git 제외)에, 연잎 사진은 `.data/lily-pads/`에 저장돼요. `.env.local`에 `OPS_ADMIN_KEY`만 넣고 `npm run dev`로 확인할 수 있어요.

## iOS 앱(TestFlight)

`ios/`는 운영 주소(https://jump-up-chi.vercel.app)를 여는 Capacitor 앱 껍데기예요. 화면과 AI 대화는 웹 배포를 그대로 쓰기 때문에 `main`에 배포하면 새 빌드 없이 앱에도 반영돼요. 앱은 사용자 에이전트에 `PoljjakApp`을 붙이고, 웹은 이걸 보고 홈 화면 설치 안내를 숨겨요. 연결이 안 되면 앱에 들어 있는 `native/www/offline.html`을 보여줘요. 기록은 앱 안에 따로 저장돼서 Safari나 홈 화면 앱의 기록과 이어지지 않아요.

```sh
npm run ios
```

설정(`capacitor.config.ts`)을 iOS 프로젝트에 반영하고 Xcode를 열어요. 시뮬레이터에서 로컬 개발 서버를 열어보려면 `CAP_SERVER_URL=http://localhost:3000 npx cap sync ios`로 바꾼 뒤 실행하고, 끝나면 `npx cap sync ios`로 운영 주소로 되돌려요.

TestFlight에 올리는 순서예요.

1. Xcode › Settings › Accounts에 Apple ID로 로그인하고, App 타깃의 **Signing & Capabilities**에서 팀 `DAEHO LEE` (`DW98Q732AD`)를 고릅니다. 등록된 번들 ID는 `io.github.oheadyonsei.poljjak`이며, `capacitor.config.ts`의 `appId`와 같아야 해요.
2. App Store Connect의 기존 앱 **폴짝 - 나만의 속도**(앱 ID `6827560889`)를 사용합니다. iPhone 홈 화면 이름은 **폴짝**이에요.
3. 실행 대상을 **Any iOS Device**로 두고 **Product › Archive** → **Distribute App** → **App Store Connect**로 올립니다. 다시 올릴 때는 빌드 번호(`CURRENT_PROJECT_VERSION`)를 하나 올려요.
4. TestFlight 탭에서 테스트 정보(베타 앱 설명, 피드백 이메일, 연락처)를 채우고 외부 테스트 그룹에 빌드를 넣어 베타 심사를 받습니다. 통과하면 이메일이나 공개 링크로 친구를 초대해요.
